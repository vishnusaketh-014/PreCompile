2.2 Exact Predictor Equations & Thresholds

1. Correlation Window & Outlier Clipping:
Accept delay x only if: x ≤ 30.0 s.
Clip outlier before EWMA update: x_clipped = max(μ - 3σ, min(x, μ + 3σ)) (once ≥ 5 samples exist).

2. EWMA Mean & Variance Formulation (α = 0.2):
μ_n = (1 - α) · μ_(n-1) + α · x_clipped
var_n = (1 - α) · (var_(n-1) + α · (x_clipped - μ_(n-1))²)
σ_n = √(var_n)

3. Reservation Prediction Window (k = 2.0, m = 0.3s):
Window = [ max(0, μ_n - 2σ_n - 0.3s), μ_n + 2σ_n + 0.3s ]

4. Confidence Gate Thresholds:
• Sample Count: N ≥ 5
• Variability: CV = σ / μ ≤ 0.5 OR σ ≤ 0.25 s (for very small means)
• Recent Hit-Rate: Hit-Rate ≥ 0.6 over last 10 predictions (once ≥ 5 predictions logged)

2.3 Reservation State Machine

+------------------------------------------------+ | early match: | | process appears before window opens | v | save + gate +-----------+ window opens +----------+ | --> passed ----->| ARMED |------------------->| ACTIVE | | +-----+-----+ +----+-----+ | | | | | window ends, | process | | no match | matched | v v | +-----------+ +----------+ | | EXPIRED | | CLAIMED +----+ +-----+-----+ +----+-----+ | | build ends | v (cgroup empty / max lifetime) | +----------+ | | CLOSED | | +----+-----+ | | v v +----------------------------------------------+ | Outcome Recorded / Model Updated | | (cgroup removed / IDLE) | +----------------------------------------------+ ^ | From any state on shutdown, fatal error, | or project disabled: +-----+-----+ | CANCELLED | +-----------+

2.4 Process Claiming & Safety Rules

  • Identity Criteria: Executable in project tool profile (gcc, clang, make, etc.); resolved working directory (via realpath) within project root; not already in a reserved cgroup.
  • Atomic Claim: Atomic test-and-set claim flag ensures exactly one process claims the reservation.
  • Ancestor Hierarchy: If multiple candidates appear concurrently, the topmost ancestor within the project is claimed; existing children are migrated into the cgroup; future children inherit automatically.
  • Safety Invariants: Real-time scheduling (SCHED_FIFO, SCHED_RR) is strictly forbidden; CPU weight is capped (cpu.weight ≤ 500); boosts have bounded maximum lifetime; stale cgroups are purged at startup.

2.5 Validation Protocol (Section 8)

  • Compared Conditions: C0 (no system/baseline), C1 (reactive boost after spawn), C2 (full PreCompile), C3 (static always-on boost).
  • 5 Ablation Studies: (A1) Reactive boost; (A2) Without confidence gate; (A3) Without contention gate; (A4) Fixed static window; (A5) Without randomized holdouts.
  • Trigger Scenarios: (A) Automatic build after save; (B) Irregular manual build (gate abstains); (C) Save without build (clean expiry).
  • Key Metrics: Build completion time (median and 95th percentile), prediction hit-rate, false-reservation rate, claim latency, CPU overhead. Evaluated over ≥50 repeated interleaved runs per condition with Mann-Whitney U significance testing.

3.2 Recorded Design Decisions

  • Single CLI entry point: Unified precompile CLI provides subcommands: daemon, status, projects, and predict.
  • /proc polling in first pass: Process detection uses /proc table polling initially, leaving netlink process connector (cn_proc) as a zero-latency later upgrade.
  • SQLite for dynamic data, YAML for settings: SQLite (precompile.db) stores projects, latency samples, prediction records, and holdout history. config.yaml is reserved exclusively for static settings.
  • Root execution with graceful degradation: Daemon runs as root for cgroup v2 operations. When run unprivileged, it degrades to observation-only mode without crashing (Stage 10).
  • Observation-first implementation: Steps 1 to 6 focus strictly on observation, learning, and gating without applying kernel scheduling modifications.
